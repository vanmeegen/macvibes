Layers, connections, and the seams that hold them apart

A local vibe-coding platform: each Claude Code session runs inside its own microsandbox MicroVM. Three views — what each layer is responsible for, how traffic crosses the trust boundary at runtime, and the interfaces that keep the parts decoupled.

01 Responsibility per layer

One job each, dependencies only ever point down

The server is a strict stack: every layer may import only from layers below it, and the rule is compiled into the build — a violation fails bun run ci. sandbox and agent are siblings over core and never import one another.

depends on (imports downward) Web mirror: pages → models → api, no back-edges

02 Runtime connections

Four channels cross the trust boundary — and only four

The MicroVM is untrusted by design (Claude Code runs there with bypassPermissions). Everything it can reach passes through a guarded host-side edge: the preview gateway, the agent gateway it dials out to, the credential proxy that injects the API token it never sees, and the egress proxy that blocks the host LAN and loopback.

originates in the untrusted VM guarded host / external traffic lifecycle control

03 Interfaces & wire protocols

The seams: swappable implementations behind one contract

Dependency inversion keeps the layers honest. Callers hold an interface; the composition root chooses the implementation. The same discipline draws the host↔VM wire protocols as strict, allow-listed message sets.

request originates in the untrusted VM host forwards to a validated destination Every VM-originated message is parsed against a fixed allow-list before the host acts on it.
